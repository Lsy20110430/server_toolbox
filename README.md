服务器检测工具箱 (Server Check Toolbox) v1.0

一个纯 Python 标准库实现的服务器网络检测工具，提供存活检测、双向连通性验证、端口扫描、防护特征识别以及域名解析五项功能。所有探测均为本机直连目标，不经过任何第三方服务、公共 API 或代理。

⚠️ 使用须知：请仅对你本人拥有或已获得书面授权的服务器使用本工具。

功能详解

1. 服务器存活检测

探测方式

1. ICMP 回声探测：调用系统 ping 命令发送 1 个探测包
2. 常用端口 TCP 探测：对端口 80, 443, 22, 3389, 8080 并发做 TCP 连接测试

判定逻辑

· 只要 ICMP 有回应 或 任一端口返回 open / closed（有 RST 响应），即判定为在线
· ICMP 无响应不代表主机离线——很多防护设备会主动拦截 ICMP

---

2. 服务器双向检测

用于确认 本机 → 服务器（去程）与 服务器 → 本机（回程）两条链路是否都通。

三级验证

层级 方法 说明
主机层 ICMP 回声往返 请求送达且回声返回，说明双向通
传输层 TCP 三次握手 握手成功意味着 SYN 到达且 SYN/ACK 返回
应用层 一次只读请求 在已建立的连接上读取回包，验证真实数据往返

常见结论

· 双向通畅：握手成功 + ICMP 有响应
· 回程可达：端口关闭但服务器回了 RST，说明回程链路通，只是该端口无服务
· 未确认双向通路：ICMP 与 TCP 均无响应，去程或回程至少一侧被阻断

---

3. 服务器端口检测

输入方式

· 直接回车 → 使用内置的 24 个常见端口清单
· 自定义输入 → 如 22,80,443,8000-8010

限制

· 单次最多探测 64 个端口（MAX_PORTS_PER_RUN），避免变成大范围扫描器
· 探测超时 2 秒，并发 32 线程

端口状态说明

状态 含义
开放 三次握手成功，有服务在监听
关闭（有响应 / RST） 服务器主动拒绝，端口无服务
无响应（被过滤） 握手包被静默丢弃，常见于防火墙策略
网络不可达 本机到目标无路由
探测出错 其他异常

安全提醒：若以下高危端口对外开放，会给出额外告警：

23 (Telnet)、135 (RPC)、139 (NetBIOS)、445 (SMB)、1433 (MSSQL)、3306 (MySQL)、3389 (RDP)、5432 (PostgreSQL)、5900 (VNC)、6379 (Redis)、27017 (MongoDB)

4. 服务器防护检测

只读探测，不发送攻击载荷、不修改目标任何状态。包含五个子项：

1. ICMP 响应策略 — 是否允许 ICMP 回声
2. 丢包策略 — 对未开放高位端口（45678, 49123, 53117）的响应方式，判断是否存在状态防火墙
3. Web 防护特征 — 分析 HTTP 响应头，识别常见 WAF / CDN：
   · Cloudflare、AWS CloudFront / ELB、Sucuri、Akamai
   · Imperva / Incapsula、F5 BIG-IP、ModSecurity 等
4. 请求头差异 — 对比常规 User-Agent 与空 User-Agent 的响应差异，判断是否配置反爬规则
5. 高危端口暴露面 — 扫描常见管理 / 数据库端口

汇总输出分三级：

· [防护] — 发现防护迹象
· [风险] — 暴露面风险
· [观察] — 中性观察

结论基于常规探测特征推断，不能替代正式的安全评估。

5. 服务器IP解析

唯一需要 DNS 查询的功能，会把域名提交给本机配置的 DNS 服务器（这是 DNS 查询的必要行为）。

输出内容

· IPv4 (A) 记录列表
· IPv6 (AAAA) 记录列表
· 解析耗时

限制：Python 标准库只能拿到地址列表，拿不到 TTL 与 CNAME 链路。如需这些信息，需安装第三方库：

```bash
pip install dnspython
```

隐私与安全设计

本工具在设计上高度重视隐私与安全：

1. 本机直连：所有探测都在本机与目标服务器之间直接完成，不经过任何第三方服务、公共 API、代理或中继，绝不把 IP 交给外部。
2. 不做 DNS 泄露：功能 1–4 只接受 IP 字面量，不做域名解析，因此不会向 DNS 泄露目标。
   · 例外：功能 5「服务器IP解析」需将域名提交给本机 DNS，且解析结果明文显示。
3. IP 脱敏显示：默认对 IP 脱敏（如 203.0.113.7 → 203.*.*.*），程序不写日志文件、不把 IP 落盘。
4. 只读探测：只做常规 TCP 连接测试、ICMP 回声探测与 HTTP 响应头分析，不发送攻击载荷、不做漏洞利用、不猜测口令、不修改目标任何状态。
5. 输入不回显：IP 输入通过 getpass 隐藏，避免明文留在屏幕上。
6. 端口数量限制：单次最多探测 64 个端口，避免沦为扫描器。

默认情况下 IP 以脱敏形式显示。如果只是在本机屏幕上看明文，可在运行前设置环境变量（仅影响显示，不改变任何网络行为）：

Windows CMD

```powershell

```

常见问题

Q1：为什么 ICMP 无响应，但工具仍判定服务器在线？

A：很多服务器出于安全考虑会主动关闭 ICMP 响应，或由上游防火墙拦截 ICMP。工具会根据 TCP 端口是否有响应（open 或 closed 都算有响应）来综合判断，因此 ICMP 无响应不等于主机离线。

Q2：为什么输入域名时提示"只接受 IP 字面量"？

A：功能 1–4 刻意不做域名解析，以避免向 DNS 泄露目标。请先用功能 5 解析域名，再复制 IP 到前四项功能中使用。

Q3：端口扫描为什么限制在 64 个以内？

A：为避免本工具被误用为大范围端口扫描器，单次探测端口数被限制为 64 个。如需检测更多端口，可分批运行。

Q4：能否获取 DNS 的 TTL 或 CNAME 记录？

A：Python 标准库的 socket.getaddrinfo 只能返回地址列表，无法获取 TTL 与 CNAME 链路。如需这些信息，请安装 dnspython 后另行处理。

Q5：为什么回显的 IP 是 203.*.*.*？

A：这是默认的脱敏显示。如需查看明文，请设置环境变量 TOOLBOX_UNMASK=1（详见上文）。

Q6：在管道或重定向场景下 IP 输入还会隐藏吗？

A：不会。当标准输入不是终端（sys.stdin.isatty() 为假）时，getpass 无法隐藏回显，此时按普通输入处理。
